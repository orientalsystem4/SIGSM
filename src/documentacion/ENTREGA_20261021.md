# Actualizacion de cancelaciones y aspecto visual

Base de trabajo: ZIP exportado desde hebe, commit 880a141.

## Cambios

- Unidad de Enlace: nueva pestana de solicitudes canceladas, con numero, elemento, origen, destino, solicitante, responsable, fecha y motivo.
- Busqueda de cancelaciones e historial por texto, sin distinguir mayusculas ni tildes.
- Retiro de los modales de demostracion de Enlace y del JavaScript que simulaba asignaciones/cancelaciones con localStorage. La asignacion sigue en asignar.php y la cancelacion desde Mis solicitudes sigue usando su controlador y MariaDB.
- Limpieza del CSS de Enlace correspondiente a esos modales y a bloques antiguos no presentes en la vista.
- Los antiguos accesos HTML de Enlace, Choferes, Enfermeria, Documentacion y seleccion de modulos ahora redirigen al PHP correspondiente. La autenticacion se verifica en PHP.
- Tema compartido: src/serviciosComunes/vistaGeneral/assets/css/tema-institucional.css. Paleta teal, tarjetas blancas, campos, botones, tablas y adaptaciones para celular. Se carga despues del CSS de cada pantalla.
- Estilo aplicado a portales, seleccion de modulos, seleccion de rol, asignacion, vistas de usuarios y documentos. El login conserva su hoja propia. Se mantienen colores de estados, alertas y categorias.
- Se corrigio el selector readonly de Enfermeria: los select editables no deben parecer bloqueados.
- Se completo cancelacion_solicitudes.sql: el archivo recibido estaba vacio.
- El volcado sigsm.sql incluye ahora los campos de cancelacion para instalaciones nuevas.
- Se incluye rutas_iniciales.sql para las seis combinaciones entre los tres hospitales de prueba. No son rutas oficiales confirmadas.

## Aplicacion sobre una instalacion existente

1. Guardar el trabajo y verificar git status. Este paquete se preparo sobre 880a141.
2. Copiar la carpeta src del paquete dentro de SIGSM, combinando carpetas y reemplazando solo los archivos incluidos. No borrar la carpeta src existente. No se incluye .env ni se cambia Docker.
3. En phpMyAdmin, ejecutar el contenido de src/documentacion/cancelacion_solicitudes.sql. Es repetible en MariaDB 10.4 y no borra solicitudes.
4. Verificar las ubicaciones con SELECT id_ubicacion, nombre FROM sigsm.ubicacion. Si 1 es Clinicas, 2 Maciel y 3 CHPR, ejecutar rutas_iniciales.sql si faltan esas rutas. No inventa distancia ni tiempo.
5. No reimportar sigsm.sql en una base que ya tenga datos. No ejecutar docker compose down -v.
6. Recargar el navegador con Ctrl+F5.

Git y SSH no actualizan por si solos la estructura de MariaDB. Cada entorno existente debe ejecutar la migracion antes de abrir las vistas que consultan sus campos. El nombre de base de los scripts es sigsm; adaptar conscientemente si el servidor usa otro.

## Verificacion antes del merge

- DTI: abrir todos los portales desde el selector de modulos.
- Enfermeria: crear una solicitud de prueba, verla en Mis solicitudes, cancelar con motivo, consultar Ver cancelacion.
- Enlace: comprobar que desaparezca de Pendientes y aparezca en Solicitudes canceladas con los mismos datos. Probar busqueda, texto sin tildes y texto inexistente.
- Una solicitud con traslado asignado no debe mostrar cancelacion en Mis solicitudes; el controlador tambien rechaza esa operacion.
- Asignar otra solicitud como DTI/coordinador y recorrer sus estados con el chofer asignado. Revisar el historial en ambos portales.
- Chofer: no debe acceder a Enfermeria pegando su URL. Enfermeria no debe administrar usuarios.
- Abrir Documentacion y usuarios, probar navegacion y formularios existentes.
- Revisar pantalla ancha y celular (menu lateral, tablas con desplazamiento y formularios).
- Revisar que las antiguas URLs HTML redirijan al PHP protegido.
- Ejecutar git diff --check y revisar git diff --stat antes del commit.
